# Playable deployment candidate

This packages the existing pilot for one dedicated **native Linux** host. It is a reviewable candidate, not a production launch or security audit. Docker Desktop/WSL testing does not qualify production isolation. Current Minecraft 1.21.11/Paper 132 is unsupported and uses offline fixture identities; supported Paper/authentication, real independent-player verification, TLS/Privy origin setup, restoration testing and the original live phase gates remain pending. The existing WSL processes share an OS identity and therefore do not provide an owner-key isolation boundary.

Focused dependency triage also blocks production release. The original companion audit reported 31 affected packages (11 moderate, 20 high). Compatible overrides replace only vulnerable `ws` 8.18.0/8.18.3 with 8.21.0; its two advisory families disappear. The resulting audit reports 30 affected packages (7 moderate, 23 high; propagated severity counts changed). Remaining high roots are Zod collection-validation memory exhaustion and malformed URI decoding denial of service. Latest Privy React 3.51.0 still requires Zod `^3.25.76`, while the advisory's fixed range starts at 4.6.6; forcing that API major is unsafe. The fixed decoder 0.5.1 is ESM, while its current `query-string` 7 caller uses CommonJS. A forced SDK downgrade or major transitive override was not applied. UUID's buffer bounds advisory remains moderate. These SDK/connector dependencies are shipped to the public authentication surface; this check does not establish that vulnerable paths are unreachable. Obtain a supported upstream fix/migration and reverify authentication before production release. The existing bot tree separately reports six moderate findings; no bot dependency changes were made by this packaging lane.

The runtime image contains no credentials. `console` and `worker` mount only an App Secret plus the scoped Privy delegate, public policy metadata, database settings and the plugin token. The offline owner key is mounted **only** by the explicit one-off `admin` profile. Never mount a host home, repository `.local`, credential directory, Docker socket, deployer/issuer keystore or entire configuration archive. The image build context excludes these paths and all existing `node_modules` and Git history. Backend, bot dependencies and companion bundles are installed from their lockfiles; Node 26.3.1 is pinned by the verified official multi-platform digest.

## Prepare a new host without starting services

1. Provision dedicated Linux accounts/storage. Runtime UID/GID is `10001:10001`, proxy is `101:101`, optional database is `999:999`. Prepare private persistent directories owned by their actual service account, mode `0700`; individual secret files must be owned by that account, mode `0600`. Verify inside the image with `stat`, because Compose bind-backed secrets can ignore advertised UID/mode settings. Do not recursively chown an existing host home or world. Copy only explicitly reviewed files into a separately prepared service directory.
2. Set the environment variables required by `compose.yaml`. `PUBLIC_CONFIG_DIR` must contain exactly `wallet-settings.json`, `market.json` and optionally `enrolled-players.json`. Set the wallet settings `credentialsFile` to `/run/agentcity-runtime/credentials.json`, `adminCredentialsFile` to `/run/agentcity-owner/owner.json`, `enrollmentFile` to `/app/.local/playable-testnet/enrolled-players.json`, and `playerOrigin` to the actual HTTPS origin including `:8443` if used. Keep the actual verified market addresses/policy fingerprints; do not regenerate wallets or deployments.
3. `RUNTIME_CREDENTIALS_FILE` contains `appSecret`, `delegateAuthorizationPrivateKey`, `delegatePublicKey` and public `ownerPublicKey`. It must not contain `authorizationPrivateKey`, raw wallet keys or owner authority. `OWNER_CREDENTIALS_FILE` is a separate offline file containing owner authorization, supplied only for a specific administrative operation. Runtime startup refuses an owner file mount and extra files in the public configuration directory. Container isolation also requires the host administrator to keep the owner file outside every runtime mount.
4. `DATABASE_SETTINGS_FILE` contains the existing `{ "databaseUrl": "..." }` format. Use a separate non-superuser application database role with permissions for the reviewed schema/migrations. Persist PostgreSQL's complete data/WAL and plugin world/native receipt journals on private volumes. Persist `AGENT_JOURNAL_DIR` separately for ownership, task plans, operations and cargo recovery. The active pointer must be `{ "owner": "agentcity-playable-pilot", "container": "agentcity-playable-00000001" }`. Copy the existing exact agent journals during an offline migration; never reset pending tasks or receipt history. `PLUGIN_TOKEN_FILE` is an individual read-only mount shared by the service needing it.
5. The optional `compose.infrastructure.yaml` shows separate persistent database and plugin volumes. Pre-provision its external volumes with the correct ownership; prepare the world with approved JARs, `eula.txt`, whitelist and server configuration before starting. It does not create a world, accept an EULA, migrate a database or upgrade Paper automatically. Its database port is loopback `55434`, Minecraft is loopback `25596`, and plugin HTTP is loopback `25597`. An existing reviewed local database/Paper deployment can instead remain external. Never connect two writers to the same world or agent journals.
6. Copy `nginx.conf.example` outside the repository, replace `wallet.example.invalid` with the exact Privy/player origin, provide a valid TLS certificate/key, and set `PROXY_CONFIG_FILE`, `TLS_CERT_FILE`, `TLS_KEY_FILE`. Only the proxy UID may read its key. The proxy exposes HTTPS `8443` and forwards five exact player routes. Every other path, including `/`, `/api/demo`, operator console assets and unknown player paths, returns `404`. Backend host checks and request-origin/session checks still apply. Register the exact HTTPS origin in Privy. No wildcard proxy rule or public mapping of `8789` is permitted.

## Review and start only after migration approval

```sh
docker compose -f ops/playable-production/compose.yaml config --quiet
docker build -f ops/playable-production/Dockerfile -t agentcity-playable:deployment-candidate .
# Stop the old worker and console, and back up/restore-check DB + world + agent journals first.
docker compose -f ops/playable-production/compose.yaml up -d console worker proxy
# Explicit one-off administrative session; owner is never in the running services:
docker compose -f ops/playable-production/compose.yaml --profile admin run --rm admin admin --verify-authority
```

The current worker uses loopback plugin, Minecraft and Ollama endpoints. Host networking is intentional for this single-host candidate; the console still binds `127.0.0.1:8789`. Keep host firewall rules denying external access to `8789`, `25597`, Ollama and PostgreSQL. Exposing the Minecraft game itself requires a separate reviewed authentication/network decision. Local worker leases hash the runtime path; `/app` and the old WSL path produce different locks. They are **not distributed fencing**, and database transaction locks do not make concurrent workers safe. Stop old writers before mounting migrated journals or starting this candidate.

Use an explicitly reviewed CLI operation for policy/enrollment changes, then remove the one-off admin container and offline owner mount. The admin profile has no public listener and never starts by default. Review the resolved Compose configuration and `docker inspect` mount/security settings before any real credentials are supplied. Keep logs free of challenge URLs, authentication tokens and secrets. Back up immutable signed-intent and receipt history with the database; reconcile existing operations after restart instead of creating replacements.

## Credential-free check

```sh
docker run --rm --read-only --user 10001:10001 --cap-drop ALL \
  --security-opt no-new-privileges --tmpfs /tmp:rw,noexec,nosuid,nodev,uid=10001,gid=10001,mode=0700 \
  -e AGENTCITY_LOCAL_PORT=18789 --network host agentcity-playable:deployment-candidate smoke
```

On an unused loopback port, verify `/player-wallet`, its bundled script and `/api/player-wallet/config` without mounting credentials. `configured:false` is expected. This checks packaging/HTTP only: it does not authenticate a human, create a provider wallet, test a payment, migrate data or qualify a production deployment.
