# Personal-agent structures and materials

This extension is a local implementation candidate until its actual-world fixture evidence is recorded. Keep the existing lobby, Survival play world, protected calculator museum, requester ownership and native material receipts. It does not qualify an independent human or production deployment.

Use `/play`, then `/agent create` if you do not already own an agent. `/agent task ...` asks the local model to propose supported physical steps. For example: “Build a small oak-plank house,” “Build a three-block-wide wall at a free offset,” or “Harvest two loose oak-plank blocks in my plot, then craft four sticks.” `/agent status` reports progress. The model cannot run server commands, create materials or authorize wallet spending.

Structures use approved solid blocks within the assigned plot: a house, tower, bridge, wall, stairs, arch or explicit relative cells, with at most 256 cells, an 8×8 footprint and six blocks of height. An offset must still fit the plot and avoid existing blocks. The west and north two-block access strips, fixed chests, foundation below the build area, other plots, lobby and museum are protected. An impossible or occupied design needs clarification or a material/space change; it must not overwrite the old shelter.

Gathering uses actual supported blocks observed in the owner's plot, excludes recorded structures and protected infrastructure, and checks real drops and pickup. A bare stone pad does not provide trees or other resources automatically. Put actual materials in the registered source chest or place supported loose resource blocks in an unused permitted cell. No fixture stock is replenished. Safe inventory recipes are one log → four planks, two planks → four sticks, and four stone → four stone bricks. Furnaces, smelting, arbitrary workbench recipes, tools, combat and unrestricted exploration are not implemented by these tools.

Completed output can remain in the agent's real inventory or be delivered to its registered destination chest. Delivery uses carried items first and withdraws only a missing amount from the registered source chest. Ask “deliver my four crafted sticks to the destination” to transfer the existing output. An agent carrying items must not be discarded or released to bypass accounting. A pending or uncertain operation keeps its original task/operation identity: inspect the report and resume/reconcile the same request rather than issuing a replacement.

Operator fixture: `node tests/playable/autonomy-live.cjs` reads existing ownership/task journals only. After the coordinated plugin/worker upgrade, `node tests/playable/autonomy-live.cjs --run` uses the existing TaskTester identity and free CityAgent2 slot, withdraws exactly two existing planks for two native resource blocks, asks for fresh native stock inspection, requests a seven-block parameterized arch at an unused offset through the model, gathers the two blocks, crafts four sticks and deposits those same carried sticks into the destination. It refuses another owner's slot, pending work, occupied cells or insufficient existing stock. It records exact material deltas and preservation of the old blocks and Ruddy's CityAgent1 binding. It does not reset, replenish, teleport an agent or impersonate Ruddy.

Free-form geometry generation remains experimental and is not qualified by the current model tests. Named structure tools accept dimensions and material selected by the model, then generate their geometry deterministically. The operator fixture uses that parameterized arch path and preserves the separate failed free-form design reports.
